# 数据来源与处理流程

本项目的地图数据来自**两个独立来源**，经离线预处理合并成一份运行时数据。
浏览器运行时**不请求任何地铁数据**（唯一的网络请求是 CARTO 底图瓦片）。

## 一图看懂

```
① 上海地铁官方数据（爬虫快照，2025-08）        ② 高德「公交信息查询」API（2026-08 拉取）
   data/raw/                                      data/raw/amap/
   ├─ shanghai_metro.json         1.5MB           └─ line_1.json … line_51.json  20 个文件
   │    站点名称 / 坐标 / 出入口…                        每条线路的真实轨道 polyline + 站点坐标
   ├─ shanghai_metro_schedule.json 4.5MB                （坐标系：GCJ-02 火星坐标）
   │    各线各方向逐站首末班时刻表
   └─ interval.json               64KB
        分星期 / 分时段发车间隔
                    │                                              │
                    └──────────────┬───────────────────────────────┘
                                   ▼
                   npm run prepare-data（scripts/prepare-data.mjs）
                   · 清洗、按站名匹配、GCJ-02 → WGS-84 坐标转换
                                   ▼
                        src/data/metro.json  ≈ 516KB
                        20 线路 · 519 站 · 60 交路（全部带真实几何）
                                   ▼
                   Vite 构建时 import 进 JS bundle → 浏览器
```

## 两个数据源分别提供什么

| 最终字段 | 来源 | 说明 |
|---|---|---|
| 站点**名称**（中/英） | ① 官方 | `name_cn` / `name_en` |
| 站点**坐标** | ② 高德（转 WGS-84） | 用高德坐标修正官方坐标，保证圆点落在轨道线上；高德没有的站退回官方坐标 |
| 线路**颜色** | ① 官方 | `line_info.color` |
| 线路/交路**几何**（曲线走向） | ② 高德 polyline | 60/60 交路全部匹配到真实轨道；匹配失败会退回站点直连（当前无失败） |
| **站序与方向**（含大小交路、支线） | ① 官方时刻表 | 按 description 分组，用首/末班时间差多数表决判断站序方向 |
| 相邻站**运行时长** | ① 官方时刻表 | 取首班、末班两组相邻站时间差的较小值，夹取 0.5–45 分钟 |
| **发车间隔** | ① 官方 interval | 按星期分组，时间窗（如 07:00-09:00）→ 间隔分钟数 |

## 关键处理点

- **坐标系转换**：官方数据是 WGS-84，高德是 GCJ-02（火星坐标），两者直接叠加会有
  300–500 米偏移。`scripts/gcj02.mjs` 做 GCJ-02 → WGS-84 逆变换后才使用。
- **站名匹配**：官方与高德站名按归一化后精确匹配（去空白、统一间隔号、剥掉高德的
  消歧后缀，如「国家会展中心(2号线)」「浦东南路(原东昌路)」）。
- **数据体积**：官方原始数据约 6MB（含大量出入口、厕所、电梯等无关字段），预处理后
  只保留运行所需字段，压到约 516KB，直接编译进前端包。

## 如何更新数据

```bash
# 只更新线路几何（高德，需要 .env 里的 Web 服务 AMAP_KEY）
npm run fetch-amap        # 已拉取的线路会跳过，--force 强制重拉

# 重新生成运行时数据（改动任一原始数据后都要跑）
npm run prepare-data
```

时刻表 / 发车间隔来自 2025-08 的官方快照，替换 `data/raw/` 下对应文件后重跑
`prepare-data` 即可。官方调图后需要重新爬取这三个文件（爬虫不在本仓库内）。

## 重要限制

**这不是实时数据。** 上海地铁没有公开的实时列车位置 API，本项目的列车位置是
「按官方时刻表 + 发车间隔理想推算」的模拟结果，不反映实际的延误、限流、临时调整或
节假日时刻。数据会随官方调图过期。界面左下角对此有注明。
